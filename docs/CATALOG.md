# 큐레이션 카탈로그 & 태그 매칭

추천 5곡 중 **무드 곡 3곡**은 `data/catalog.json`에서 **태그 매칭**으로 고릅니다.
**장소 곡 2곡**은 AI가 실시간으로 추천합니다.

## 1. 전체 흐름

```
[여행지 + 무드]
   │
   ├─ Gemini 호출 1번 (카탈로그는 보내지 않음 → 프롬프트 약 1천 자)
   │     · 장소 곡 2곡
   │     · 여행지 프로필: country · season · scenery · vibes   ← js/tags.js 어휘로 enum 제한
   │
   └─ 브라우저 js/matcher.js
         1. 제외: 여행지 나라 = 곡 market (단, KR은 예외) · 장소 곡과 같은 곡
         2. 점수: 곡 태그 ↔ 여행지 프로필 + 무드 (아래 표)
         3. 선택: 다양성 보정(같은 나라·템포 감점) + 상위 8곡 안에서 가중 무작위 → 3곡
         4. 설명: 일치한 태그로 추천 이유 문장 + #태그 표시
```

AI는 여행지가 **어떤 곳인지**(태그)만 판단합니다. **어떤 곡이 맞는지**는 투명한 점수 규칙이 정합니다.
그래서 결과를 설명할 수 있고, 가중치를 조정할 수 있고, 같은 입력이면 비슷한 품질이 나옵니다.

## 2. 태그 어휘 (`js/tags.js`)

카탈로그와 여행지 프로필은 **같은 단어 목록**을 씁니다. 목록 밖의 단어는 매칭되지 않습니다.

| 태그 | 의미 | 값 |
|---|---|---|
| `moods` | 듣는 상황 (사용자 칩) | 드라이브, 산책, 카페, 야경, 비 오는 날, 비행기 안 |
| `scenery` | 풍경: 눈에 **보이는 것** | 바다, 섬, 산, 숲, 호수·강, 시골·들판, 설경, 사막, 도시, 골목, 유적·고도, 도로 |
| `vibes` | 분위기: **느껴지는 것** | 낭만, 여유, 활기, 고요, 레트로, 이국적, 쓸쓸함, 설렘, 모험, 힐링 |
| `seasons` | 어울리는 계절. **빈 배열 = 사계절** | 봄, 여름, 가을, 겨울 |
| `times` | 어울리는 시간대. **빈 배열 = 언제든** | 낮, 밤 |
| `tempo` | 곡 템포 | slow, mid, fast |
| `market` | 곡의 나라 (현지 곡 제외에 사용) | KR, US, UK, JP … (2글자 대문자) |

### 태그 붙이는 기준
- **풍경·분위기는 각각 2개를 권장합니다 (최대 3개).** 태그가 많을수록 어디에나 맞는 곡이 되어 변별력이 떨어집니다. 점수도 각각 2개까지만 인정합니다.
- **풍경 태그는 이렇게 판단합니다:** 이 곡을 틀어 둔 장면을 떠올렸을 때 창밖에 보이는 것. 가사 내용보다 사운드의 인상이 우선입니다.
- **계절·시간대는 확실할 때만 넣습니다.** 크리스마스 곡이나 여름 노래처럼 분명한 경우입니다. 다른 계절이면 감점되므로 애매하면 비워 두세요.

## 3. 점수 규칙 (`js/matcher.js`의 `WEIGHTS`)

| 항목 | 점수 | 설명 |
|---|---|---|
| 무드 일치 | +3 | 사용자가 고른 상황이 곡의 `moods`에 있을 때 |
| 풍경 일치 | 개당 +2 (최대 2개) | 곡 `scenery` ∩ 여행지 `scenery` |
| 분위기 일치 | 개당 +2 (최대 2개) | 곡 `vibes` ∩ 여행지 `vibes` |
| 계절 | 일치 +1.5 / 사계절 곡 +0.5 / 불일치 −1.5 | 여행지의 **오늘 기준** 계절 (AI가 남반구·열대까지 판단) |
| 시간대 | 일치 +1 / 불일치 −1 | 무드가 시간대를 암시할 때만 (야경 → 밤, 산책 → 낮) |
| 템포 | +1 | 무드가 원하는 템포 (드라이브 → mid·fast). 무드가 없으면 분위기에서 추정 (고요 → slow) |
| 최근 본 곡 | −3 | 이 브라우저에서 최근 보여준 30곡 |
| 다양성 | 같은 나라 −1.5, 같은 템포 −0.5 | 이미 뽑힌 곡과 비교해 곡마다 다시 계산 |

선택은 **상위 8곡 안에서 점수가 높을수록 잘 뽑히는 가중 무작위**입니다(temperature 1.2). 1등은 자주 나오지만 매번 같은 3곡이 나오지는 않습니다.

### 예시: 교토, 가을, 무드 없음
프로필은 `JP · 가을 · 유적·고도/골목/호수·강 · 고요/낭만/레트로`입니다. JP 곡 4곡은 제외됩니다.
```
7.5  IU - 밤편지          풍경 호수·강 +2, 분위기 낭만·고요 +4, 계절 무관 +0.5, 템포 slow +1
6.5  성시경 - 거리에서     풍경 골목 +2, 분위기 고요 +2, 계절 가을 +1.5, 템포 slow +1
5.5  Norah Jones - …      풍경 골목 +2, 분위기 낭만 +2, 계절 무관 +0.5, 템포 slow +1
```

## 4. 튜닝·검증 도구

```bash
node tools/check-catalog.mjs                 # 어휘·필수 필드·중복 검사 + 나라/무드/풍경/분위기 분포
node tools/match-preview.mjs --dest 교토 --country JP --season 가을 \
  --scenery 유적·고도,골목 --vibes 고요,낭만 [--mood 산책] [--runs 200]
                                             # 점수 상위 곡, 점수 내역, 추천 이유, 반복 선택 시 등장 빈도
```
- 브라우저에서는 `?debug`를 붙이면(예: `/?debug`, `/?demo&debug`) 보딩패스 아래에 **여행지 프로필과 곡별 점수 내역**이 나옵니다.
- **특정 곡이 너무 자주 나오면** `match-preview`의 등장 빈도를 확인하세요. 대부분 태그가 너무 넓게 붙은 경우입니다.

## 5. 스키마
```json
{ "id": "c001", "title": "밤편지", "artist": "IU", "year": 2017, "market": "KR",
  "moods": ["산책", "야경", "카페"], "seasons": [], "times": ["밤"], "tempo": "slow",
  "scenery": ["도시", "호수·강"], "vibes": ["낭만", "고요"], "videoId": null }
```
- `id`: `c` + 3자리 이상 숫자. 한 번 정한 id는 바꾸거나 재사용하지 않습니다. 최근 본 곡 기록이 id를 씁니다.
- `title`, `artist`: 공식 원어 표기. YouTube 검색어로도 쓰입니다.
- `videoId`: 대표 영상 ID (공식 MV나 Topic 채널 우선). 모르면 `null`.

## 6. 100곡 리스트 만들기 — 다른 AI에게 줄 프롬프트

아래 프롬프트를 그대로 붙여넣고, 결과를 `data/catalog.json`의 `tracks`에 넣은 뒤 `node tools/check-catalog.mjs`로 검사하세요.

````text
여행 중에 듣기 좋은 대중적인 곡 100곡의 목록을 JSON 배열로 만들어 주세요.

조건
- 실제로 존재하고 YouTube에서 쉽게 찾을 수 있는 유명한 곡만. 확실하지 않은 곡은 넣지 마세요.
- 나라 비율: KR 30 · US 30 · UK 15 · JP 15 · 기타(FR, BR, ES, SE 등) 10
- 한 아티스트는 최대 2곡. 시대(1960s~2020s)와 템포를 고르게.
- 아래 6개 무드마다 최소 15곡 이상이 해당되도록.
- 태그는 반드시 아래 목록의 단어만 그대로 사용 (띄어쓰기·가운뎃점 포함).

필드와 허용 값
- id: "c031"부터 순서대로
- title, artist: 공식 원어 표기
- year: 발표 연도 (정수)
- market: 아티스트 나라 2글자 코드 (영국은 UK)
- moods (1~3개): 드라이브, 산책, 카페, 야경, 비 오는 날, 비행기 안
- seasons (확실할 때만, 아니면 []): 봄, 여름, 가을, 겨울
- times (확실할 때만, 아니면 []): 낮, 밤
- tempo: slow, mid, fast 중 하나
- scenery (2개, 최대 3개 — 이 곡을 틀었을 때 창밖에 보일 법한 풍경):
  바다, 섬, 산, 숲, 호수·강, 시골·들판, 설경, 사막, 도시, 골목, 유적·고도, 도로
- vibes (2개, 최대 3개): 낭만, 여유, 활기, 고요, 레트로, 이국적, 쓸쓸함, 설렘, 모험, 힐링
- videoId: null

출력 형식: 한 곡을 한 줄로, 다른 설명 없이 JSON 배열만.
[
{ "id": "c031", "title": "…", "artist": "…", "year": 2000, "market": "US", "moods": ["…"], "seasons": [], "times": [], "tempo": "mid", "scenery": ["…", "…"], "vibes": ["…", "…"], "videoId": null },
…
]
````

받은 뒤 확인할 것:
1. `check-catalog`에서 오류가 0개인지 확인합니다. 어휘 밖의 태그와 중복을 여기서 잡습니다.
2. 분포를 봅니다. 산·숲·유적·고도·이국적처럼 비어 있는 태그가 있으면, 그 태그 위주로 20~30곡을 추가로 요청합니다.
3. 아는 곡 위주로 실존 여부와 태그를 빠르게 훑어봅니다.
4. `match-preview`로 대표 여행지 3~4곳을 돌려 봅니다. 예: 바다 휴양지 / 유럽 고도 / 대도시 야경 / 눈 덮인 산.

## 7. 영상 ID 운영
```bash
YT_API_KEY=AIza... node tools/resolve-catalog.mjs [--limit 90]   # 비어 있는 videoId 채우기 (곡당 100 units)
node tools/resolve-catalog.mjs --verify                          # 저장된 영상이 살아 있는지 확인 (oEmbed, 할당량 없음)
```
- 자동 검색은 첫 번째 결과를 그대로 씁니다. 커버나 라이브 영상이 걸릴 수 있으니 **로그를 보고 검수**하세요.
- `--verify`는 주 1회 실행을 권장합니다. 깨진 영상은 `videoId`를 비워 두므로 다음 resolve 때 다시 찾습니다.
- 영상 ID를 얼마나 오래 저장해도 되는지는 YouTube API 개발자 정책을 확인하고 지켜야 합니다.
