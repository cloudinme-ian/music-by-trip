# 여행지 사진 기능 (계획 · 미구현)

> 상태: **논의 정리, 코드 미반영** (2026-10-04)
> 보딩패스의 첫 곡 위쪽에 작가가 직접 찍은 여행지 사진을 띄우고, 작게 카피라이트 문구를 표시하는 기능입니다.

## 1. 결론
- 지금 구조(정적 페이지 + 태그 매칭)에 그대로 붙일 수 있습니다. 기존 기능은 바뀌지 않습니다.
- **꼭 가입해야 하는 외부 서비스는 없습니다.** 사진 수백 장까지는 저장소와 GitHub Pages로 충분합니다.

## 2. 사진 고르는 방법
곡 카탈로그와 **같은 태그 어휘**(`js/tags.js`: 나라·계절·풍경·분위기)를 사진에도 붙입니다. AI가 만든 여행지 프로필과 비교해 고릅니다.

1. **장소 이름이 정확히 같으면** 그 사진을 씁니다. 예: 교토 → 교토에서 찍은 사진.
2. **없으면 태그 점수가 가장 높은 사진**을 씁니다. 예: 교토 → 비슷한 골목·고도 분위기 사진. `js/matcher.js`의 점수 방식을 재사용합니다.
3. **점수가 기준에 못 미치면 사진 없이** 지금처럼 표시합니다. 엉뚱한 사진보다 안 보이는 편이 낫습니다.

## 3. 구성 (안)
| 항목 | 내용 |
|---|---|
| 사진 파일 | `photos/` 폴더. 가로 1600px 정도의 WebP, 장당 200~300KB |
| 사진 정보 | `data/photos.json`. 곡 카탈로그처럼 한 장을 한 줄로 기록 |
| 위치 | 보딩패스 요약 문장과 첫 곡 사이 (절취선 위) |
| 카피라이트 | 사진 아래쪽 모서리에 작은 글씨로 겹쳐 표시. 밝은 사진에서도 읽히도록 어두운 그라데이션을 깝니다 |
| 이미지 저장 | 사진과 문구가 PNG에 함께 담깁니다. 같은 사이트의 파일이라 지금의 저장 기능이 그대로 동작합니다 |

`data/photos.json` 항목 예시 (안):
```json
{ "id": "p001", "file": "photos/kyoto-gion-2025.webp", "place": "교토", "country": "JP",
  "year": 2025, "seasons": ["가을"], "scenery": ["골목", "유적·고도"], "vibes": ["고요", "레트로"],
  "alt": "해 질 녘 기온 거리의 목조 상점가" }
```

## 4. 주의할 점
- **화면에 겹친 문구는 보호 효과가 약합니다.** 사진 파일 주소를 직접 열면 문구 없이 받을 수 있습니다. 실질적으로 보호하려면 **사진 파일 자체에 워터마크를 새겨서** 올립니다. 우클릭 막기 같은 방법은 쉽게 우회됩니다.
- **위치정보(EXIF GPS)를 반드시 지웁니다.** 휴대폰 사진에는 촬영 위치가 들어 있어 개인정보가 노출될 수 있습니다.
- **저장소가 공개라서 사진 원본도 GitHub에 공개됩니다.**
  - README에 "코드와 별개로 사진의 저작권은 작가에게 있음"을 명시합니다.
  - 필요하면 저장소를 비공개로 하거나 사진만 따로 저장합니다.
- **원본(3~10MB)은 그대로 올리지 않습니다.** 크기를 줄여야 모바일에서도 빠르게 열립니다.

## 5. 준비할 서비스·도구
| 구분 | 필요 여부 | 내용 |
|---|---|---|
| 외부 서비스 | **없음** | 저장소 + GitHub Pages로 충분합니다 |
| 이미지 변환 스크립트 | 필요 (무료, 로컬) | Node + sharp. 크기 조절, WebP 변환, GPS 제거, 워터마크 새기기를 한 번에 처리 |
| 사진 저장소·CDN | 선택 | 사진이 수천 장이 되거나 저장소와 분리하고 싶을 때 Cloudflare R2나 Cloudinary를 씁니다. 이미지 저장 기능을 위해 CORS 설정이 필요합니다 |
| 사진 자동 태깅 | 선택 | 지금 Gemini 키로 사진을 보고 태그 초안을 만듭니다. 곡 카탈로그처럼 사람이 검수합니다 |

## 6. 준비할 것 (작가)
1. **사진:** 장소별로 1장 이상. 가로 사진이 보딩패스에 잘 맞습니다.
2. **사진별 정보:** 장소 이름, 나라, 찍은 연도, 태그(풍경·분위기·계절), 사진 설명 한 줄. 사진 설명은 화면 낭독용 대체 텍스트로 씁니다.
3. **카피라이트 문구:** 표기할 이름이나 닉네임과 형식. 예: `© 2026 홍길동` 또는 `Photo © 홍길동. All rights reserved.`

## 7. 결정할 것 (TBD)
- [ ] 정확히 같은 장소의 사진이 없을 때, 비슷한 분위기의 다른 장소 사진을 보여줄지
- [ ] 맞는 사진이 없을 때 사진 칸을 비울지, 기본 사진을 쓸지
- [ ] 워터마크를 사진 파일에 새길지, 화면 표시만 할지
- [ ] 사진을 공개 저장소에 둘지, 별도 저장소나 CDN에 둘지

## 8. 구현 범위 (준비되면)
1. `data/photos.json` 스키마와 검증 도구. `tools/check-catalog.mjs`와 같은 방식입니다.
2. 사진 변환 스크립트: `tools/prepare-photos.mjs` (리사이즈·WebP·GPS 제거·워터마크).
3. 사진 고르는 로직: 장소 이름 우선 → 태그 점수 → 기준 미달이면 표시하지 않음.
4. 보딩패스에 사진과 카피라이트 표시. 라이트·다크 모드와 이미지 저장에서도 확인합니다.
5. README에 사진 저작권 고지를 추가합니다.
6. `docs/AGENTS.md`에 작업 카드를 추가합니다. 담당은 ui-designer, frontend-dev, catalog-curator입니다.
