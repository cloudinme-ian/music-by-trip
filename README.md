# 🎧 Music by Trip — 여행지 음악 추천

> **"어디로 떠나세요? 그곳에 어울리는 노래 5곡을 챙겨드릴게요."**

여행지를 입력하면 AI가 그 장소의 분위기·문화·풍경에 어울리는 음악 **5곡**을 골라주고,
각 곡의 **YouTube / YouTube Music 링크**와 (가능하면) **한 번에 재생할 수 있는 플레이리스트 링크**를 만들어 주는 단일 HTML 웹 페이지입니다.

---

## 1. 컨셉

### 1.1 한 줄 정의
여행지 → AI 큐레이션 → 5곡 + 유튜브 링크 + 플레이리스트. **"여행용 보딩패스에 찍혀 나오는 사운드트랙"**.

### 1.2 왜 필요한가
- 여행 전/중에 "이 도시에 어울리는 음악"을 찾으려면 블로그·플레이리스트를 한참 뒤져야 합니다.
- 장소에는 고유한 정서가 있습니다. 교토의 골목, 리스본의 언덕, 제주의 해안도로 — 같은 노래라도 장소가 의미를 바꿉니다.
- AI는 장소의 **현지 음악(로컬 아티스트·전통 장르)** 과 **글로벌 감성 곡**을 섞어 맥락이 있는 추천을 할 수 있습니다.

### 1.2.1 5곡의 구성: 장소 곡 2 + 무드 곡 3
| 구분 | 곡 수 | 출처 | 역할 |
|---|---|---|---|
| **장소 곡** (`LOCAL` 표시) | 2 | AI 실시간 추천 | 현지 언어·장르·아티스트, 또는 그 장소를 노래한 곡 |
| **무드 곡** | 3 | 사람이 검수한 **큐레이션 카탈로그**(`data/catalog.json`)에서 **태그 매칭**으로 선택 | 한국·미국·영국·일본 등 대중적인 곡 중 여행지 풍경·분위기·계절·무드에 맞는 곡 |

AI는 여행지의 **태그 프로필**(나라·계절·풍경·분위기)만 만들고, 곡 선택은 `js/matcher.js`의 점수 규칙이 합니다 → 추천 이유를 태그로 설명할 수 있고(`#바다 #활기`), 가중치로 튜닝할 수 있습니다.
무드 곡은 영상 ID를 미리 저장해 두므로 **YouTube API 할당량을 쓰지 않고**, AI가 곡을 지어낼 위험도 없습니다. 자세한 내용은 [docs/CATALOG.md](docs/CATALOG.md).

### 1.3 핵심 사용자 흐름
```
[여행지 입력] ──▶ [무드 선택(선택)] ──▶ [추천 받기]
                                         │
                       ┌─────────────────┴─────────────────┐
                       ▼                                   ▼
   AI(Gemini): 장소 곡 2 + 여행지 태그 프로필     (YouTube API 키가 있으면)
   matcher: 프로필 ↔ 카탈로그 태그 점수 → 3곡      장소 곡 2곡만 영상 ID 검색
                       │                                   │
                       └─────────────────┬─────────────────┘
                                         ▼
                 [보딩패스 형태의 결과 카드]
                  · 곡별 YouTube / YouTube Music 링크
                  · ▶ 전체 재생 플레이리스트 링크
                  · 이미지로 저장(보딩패스 PNG) · 목록 복사
```

### 1.4 추천 원칙 (AI 프롬프트에 반영)
1. **장소성은 2곡만** — 장소 곡(현지 언어·장르·아티스트, 또는 그 장소를 노래한 곡)은 실시간 2곡이 담당. 국내 여행지는 "그 지역을 노래한 곡/그 지역 출신 아티스트"를 장소 곡으로 봄
2. **나머지는 카탈로그에서** — 무드 곡 3곡은 태그 점수로 고르고, 여행지 현지 곡(예: 일본 여행지에 JP 곡)은 제외, 같은 나라·템포는 감점해 고르게
3. **다양성** — 5곡의 아티스트가 겹치지 않고, 시대·템포가 적당히 섞이도록
4. **실존성** — 실제로 존재하고 유튜브에서 찾을 수 있는 곡만 (가상의 곡 금지)
5. **이유 설명** — 곡마다 "왜 이 장소에 어울리는지" 한 문장
6. **무드 반영** — 사용자가 고른 상황(드라이브, 산책, 야경, 비 오는 날 등)을 우선 고려

## 3. 기술 구조

빌드 도구 없이 동작하는 **정적 웹 페이지**(HTML + CSS + ES Module JS)입니다.

```
music-by-trip/
├── index.html              # 페이지 마크업
├── css/style.css           # 보딩패스 디자인, 라이트/다크 테마
├── js/
│   ├── app.js              # UI 상태 관리, 렌더링
│   ├── config.js           # 기본값, localStorage 키 관리
│   ├── prompt.js           # AI 공통 프롬프트 + 응답 스키마 + 응답 정규화 (모든 AI 공급자가 공유)
│   ├── tags.js             # 태그 어휘 (카탈로그·여행지 프로필·검증 도구 공용)
│   ├── matcher.js          # 태그 매칭: 점수 규칙(WEIGHTS), 다양성 보정, 가중 무작위 선택, 추천 이유 생성
│   ├── catalog.js          # 카탈로그 로딩, 최근 본 곡 기록
│   ├── youtube.js          # 링크 생성, 영상 검색, 플레이리스트 링크
│   ├── sample.js           # API 키 없이 디자인 확인용 샘플 데이터
│   └── providers/
│       ├── index.js        # AI 공급자 레지스트리 (교체/추가 지점)
│       └── gemini.js       # Google Gemini 구현
├── data/catalog.json       # 큐레이션 카탈로그 (무드 곡 후보, videoId 포함)
├── tools/
│   ├── check-catalog.mjs   # 카탈로그 검증 (어휘·중복·분포)
│   ├── match-preview.mjs   # 여행지 프로필로 매칭 결과·점수·빈도 미리보기
│   └── resolve-catalog.mjs # 카탈로그 videoId 채우기 / 깨진 영상 확인
├── docs/AGENTS.md          # 다중 에이전트 작업 계획 (draft)
├── docs/CATALOG.md         # 태그 어휘·점수 규칙·스키마·100곡 생성 프롬프트·운영 방법
└── .claude/agents/         # Claude Code 서브에이전트 정의 (draft)
```

### 3.1 AI 공급자 추상화
모든 공급자는 같은 시그니처를 따릅니다.
```js
recommend({ apiKey, model, destination, mood }) → Promise<{
  destination: string,      // 정규화된 여행지 이름
  code: string,             // 3글자 공항 코드 스타일 약어 (예: KYO)
  summary: string,          // 장소 분위기 한 문장
  profile: { country, season, scenery[], vibes[] },   // js/tags.js 어휘
  tracks: [{ title, artist, year, reason, videoId, source: 'live' }]   // 장소 곡 2
}>
// 앱이 matcher.selectTracks(catalog, { profile, mood })로 무드 곡 3곡(source: 'catalog', tags, score)을 붙임
```
공급자는 `js/prompt.js`의 `buildPrompt` / `RESPONSE_SCHEMA` / `normalizeRecommendation`을 공유합니다.
처음에는 **Gemini**만 구현되어 있고, 이후 Claude / OpenAI 등을 `js/providers/`에 파일 하나 추가 + `index.js` 등록만으로 붙일 수 있습니다.

### 3.2 Gemini 호출
- 엔드포인트: `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
- 인증: `x-goog-api-key` 헤더
- `generationConfig.responseMimeType = "application/json"` + `responseSchema`로 **구조화된 JSON 응답**을 강제
- 프로필의 `season` / `scenery` / `vibes`는 태그 어휘로 **enum 제한** (정규화 단계에서도 어휘 밖 값 제거)
- 카탈로그를 프롬프트에 넣지 않으므로 카탈로그가 커져도 토큰 비용이 늘지 않음
- 기본 모델: `gemini-2.5-flash` (설정 화면에서 변경 가능)

### 3.3 유튜브 링크 & 플레이리스트 전략
AI는 곡명/아티스트는 잘 알지만 **유튜브 영상 ID는 정확히 알지 못합니다**(지어낼 위험). 그래서 단계적으로 처리합니다.

| 단계 | 조건 | 결과 |
|---|---|---|
| 기본 | Gemini 키만 있음 | 무드 곡: 카탈로그에 저장된 **실제 영상 링크**(videoId가 채워진 경우) · 장소 곡: 검색 링크 · videoId 2개 이상이면 플레이리스트 |
| 확장 | YouTube Data API 키도 있음 | **장소 곡 2곡만** 검색해 영상 링크 + 썸네일 + **▶ 전체 재생 플레이리스트 링크** |

플레이리스트 링크는 로그인 없이 만들 수 있는 YouTube의 임시 재생목록 URL을 사용합니다.
```
https://www.youtube.com/watch_videos?video_ids=ID1,ID2,ID3,ID4,ID5
```
> 사용자 계정에 **저장되는 정식 플레이리스트**를 만들려면 OAuth 로그인 + `playlists.insert` 권한이 필요합니다. 이는 로드맵(5장)에 있습니다.

> ⚠️ YouTube Data API `search.list`는 호출당 100 units, 기본 일일 할당량은 10,000 units.
> 카탈로그 도입으로 추천 1회 = 2곡 = 200 units (이전 500). 서비스 규모에서는 공용 캐시 프록시가 추가로 필요합니다 → 로드맵.

## 4. 시작하기

### 4.1 Gemini API 키 발급
1. [Google AI Studio → API Keys](https://aistudio.google.com/apikey) 접속 후 Google 계정으로 로그인
2. **Create API key** 클릭 → 프로젝트 선택(또는 새로 생성)
3. 발급된 키(`AIza…`)를 복사
4. 페이지 우측 상단 **⚙ 설정**에 붙여넣고 저장

### 4.2 (선택) YouTube Data API 키 발급 — 플레이리스트 링크용
1. [Google Cloud Console](https://console.cloud.google.com/) → 프로젝트 선택
2. **API 및 서비스 → 라이브러리** → `YouTube Data API v3` 검색 → **사용 설정**
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키**
4. 권장: 키 제한에서 **API 제한 = YouTube Data API v3**, **애플리케이션 제한 = HTTP 리퍼러**(배포 도메인)
5. 페이지 **⚙ 설정**의 YouTube API 키 칸에 입력

### 4.3 실행
ES Module을 사용하므로 `file://`로 열면 동작하지 않습니다. 간단한 로컬 서버로 여세요.
```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```
키 없이 디자인만 보려면 `http://localhost:8000/?demo` 또는 화면의 **샘플 보기**. `&debug`를 붙이면 매칭 점수 내역이 보입니다.

### 4.3.1 카탈로그 영상 ID 채우기
```bash
YT_API_KEY=AIza... node tools/resolve-catalog.mjs          # videoId 없는 곡 검색 (곡당 100 units, 기본 최대 90곡)
node tools/resolve-catalog.mjs --verify                     # 저장된 영상이 살아 있는지 확인 (키·할당량 불필요)
```

### 4.4 보안 주의
- API 키는 **브라우저 localStorage에만** 저장되며 이 저장소/서버로 전송되지 않습니다.
- 클라이언트에서 키를 직접 사용하는 구조는 **개인용/프로토타입**에 적합합니다. 공개 배포 시에는 키를 숨기는 프록시(서버리스 함수 등)를 두세요 → 로드맵.
- 키를 코드에 하드코딩하거나 커밋하지 마세요.
